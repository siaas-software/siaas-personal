# SIAAS Personal v1.1.0-rc.4 — experimental release candidate

This experimental source release candidate includes the first-party Personal
lifecycle integrated through Personal PR #30 and SIAAS CLI PR #5. Automated,
type, build, temporary SQLite/API, headless browser and Linux packaging checks
passed during RC4 preparation. Exact release artifact provenance and checksums
must be verified against the published `v1.1.0-rc.4` tag and assets. Native GUI,
real-model and public CLI acceptance are separate activities.

The earlier `v1.1.0-rc.3` release is unchanged and **is not compatible**
with the new standalone CLI M2 install/update protocol.

## Functional scope

RC4 carries the first-party lifecycle declaration and Personal's
install-only/update/uninstall engine for **Linux x64 only**. The implementation was integrated through
[Personal PR #30](https://github.com/siaas-software/siaas-personal/pull/30)
and [CLI PR #5](https://github.com/siaas-software/siaas-cli/pull/5).
Earlier local-fixture tests do not certify public RC4 lifecycle acceptance.

The implementation reuses Personal's source-build engine and an application-owned,
verified Node.js runtime; it does not require globally installed Node/npm or
automatically launch Electron. Stable and candidate installations use separate
managed roots. Update refuses downgrade and unreviewed changes to persistence
code, takes a bounded cold backup of the stopped profile and retains the previous
application generation. Uninstall removes owned software/runtime/cache but leaves
the user profile, backups, and unrelated installations intact.

Official source npm scripts run with the ordinary user's permissions, **not**
inside a new process/network/filesystem sandbox. This accepted trust model applies
only to immutable, verified official first-party releases; it is not arbitrary
source execution. OS security policies and Electron sandbox protections remain.

## Measured scope, not a release certification

Using locally constructed trusted source fixtures and real npm/Next/Electron build
tools, Linux x64 backend install, reinstall, RC-to-RC update, rejected downgrade,
deliberately failed build preserving active metadata/data, and compiled-CLI
uninstall/repeated uninstall passed in 93.08 seconds. Evidence:
[CLI native success](https://github.com/siaas-software/siaas-cli/blob/82d89c7eda59b160d6cabb5d7b69ddc94f01ef2e/docs/m2-native-success.md).

**Not yet demonstrated:** install/update through the compiled CLI against a
published compatible Personal source release, graphical Electron/descendant
lifecycle, real database migrations, recovery from arbitrary interruption, or
native Personal CLI lifecycle on Windows, macOS, and ARM64. Cold backup is limited
to 1 GiB and does not auto-restore or downgrade SQLite schemas. Stale locks require
explicit inspection. Do not call M2 publicly complete based on the local fixture.

## Source distribution and acceptance

Keep the existing **exactly 12 source-release assets** and verified Node 24.22.0
runtime, with six source/runtime manifests. The CLI first-party declaration inside
the immutable source ZIP is limited to `linux-x64` and is verified by CLI #5.
The existing legacy install-rc scripts remain available for other targets; six
manifest records do not mean six native CLI targets are supported.

Once the release is published and its assets are verified, a compatible
standalone CLI can select RC4 using `siaas install personal --rc` or
`--version 1.1.0-rc.4`. If the tag/assets are unavailable, installation must
fail without running a legacy installer. The public CLI install/uninstall path
requires separate positive acceptance on a disposable Linux x64 host.

An **update using two published compatible releases** cannot be demonstrated
with RC4 alone: RC3 is a legacy release without the new first-party capability.
A later compatible RC (or separately reviewed equivalent) is required for that
specific public-path acceptance.

Read the [prepublication validation snapshot](1.1.0-rc.4-readiness.md) and
[native test limits](1.1.0-rc.4-windows.md) before any installation decision.
Do not publish native installers, update manifests, logs or build output as part
of the source-only release. Never change the historical tags or stable Latest.
