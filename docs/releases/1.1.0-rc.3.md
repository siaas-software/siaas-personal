# SIAAS Personal v1.1.0-rc.3

Release preparation only: not tagged or published. RC3 packages the functionality
already integrated on develop at `741b531376c93262c5d15354faf14747fbcf97cc`.
It is an experimental prerelease, not a stable upgrade or native acceptance claim.

## Changes since RC2

- Six official templates: Computer Science Study, Production Planning, Personal
  Finance, Construction Cost Analysis, Technical Documentation and Materials
  Procurement.
- Centralized semantic palettes for template cards and new projects; compatible
  import/export and preservation of custom colors and existing user data.
- README, contributor guidance and historical release/audit documentation.

The preparation changes release version metadata, changelog, these documents and
standalone packaging cleanup. Repeated builds omit earlier app-root `dist` and
`dist-source` artifacts without removing dependency output. No application feature,
dependency version, database migration or security setting changes. Draft PRs #20
(Electron testing infrastructure) and #21
(CLI lifecycle audit) are excluded. SIAAS CLI v0.1.0 cannot install Personal;
`siaas install personal` is not implemented in M1.

## Distribution

Use the existing source-installation contract: exactly 12 release assets, six
OS/architecture manifests and managed Node 24.22.0. The reviewed source is built
locally into the desktop application; users do not need global Node/npm changes.
GitHub-generated source archives are not substitutes for the verified source ZIP.

Targets are Windows (`win32`), macOS (`darwin`) and Linux, each x64 and arm64.
Manifest coverage is not proof of native acceptance on all six targets.
Source generation and verification derive the version from package metadata;
the existing `rc.N` validators and installer scripts need no RC3-specific change.

Native EXE/DMG/ZIP/AppImage/DEB packages are local test artifacts only, excluded
from this release. The existing verifier rejects extra assets both locally and
on the published release, enforcing the source-only inventory. Do not upload
`dist/*`, `latest*.yml`, stable native update manifests or build diagnostics.
Native packages retain the stable identity and default profile; test them only
inside disposable VMs under the checklist in `WINDOWS_TESTING.md`.

## Explicit installation after publication

Before publication these commands cannot resolve RC3. Download `install-rc.sh`
or `install-rc.ps1` from the exact RC3 release, review it and verify its SHA-256
against `SHA256SUMS.txt` and GitHub asset digest metadata. Checksums provide
integrity, not an independent publisher signature. Obtain the user's informed
installation consent; do not pipe an unreviewed remote script into a shell.

macOS/Linux, from the directory containing the verified script:

```bash
export SIAAS_RELEASE_TAG=v1.1.0-rc.3
export SIAAS_INSTALL_DIR="$HOME/.local/share/siaas-personal-rc3-source"
bash ./install-rc.sh
bash "$SIAAS_INSTALL_DIR/launch-rc.sh"
```

Windows, in a normal PowerShell session after verifying the script:

```powershell
$env:SIAAS_RELEASE_TAG = 'v1.1.0-rc.3'
$env:SIAAS_INSTALL_DIR = Join-Path $env:LOCALAPPDATA 'SIAAS Personal RC3 Source'
& .\install-rc.ps1
& (Join-Path $env:SIAAS_INSTALL_DIR 'launch-rc.cmd')
```

These explicit roots keep RC3 separate from both stable and existing RC2 source
installations; the managed RC profile is under the selected root. Never point
`SIAAS_INSTALL_DIR` at a stable/RC2 root or copy a live personal database there.
PowerShell policy, Gatekeeper, quarantine, antivirus and Electron sandboxing remain
enabled. If the OS blocks execution, record the block rather than bypassing it.

## Limits and preservation

Read `READINESS.md` and `WINDOWS_TESTING.md` before testing. Real Ollama inference,
graphical runtime and native Windows/macOS acceptance remain separate checks.
The existing moderate ExcelJS/uuid advisory and artifact-specific third-party
license obligations remain documented in the source repository.
Rollback does not reverse database migrations; use disposable test data and
backups. Native packages have no candidate auto-update channel. Source update
discovery remains stable-only; do not use it as an RC3 selector.

Any later publication must use GitHub prerelease=true and Latest=false, preserving
stable v1.0.0, immutable RC2, main, CLI and the website. No publication is authorized
by this document alone.
