# RC4 native acceptance limits — Linux, Windows and macOS

**RC4 native-acceptance scope (recorded during release preparation).** The source-release package maintains
six OS/architecture manifest records, but the new standalone CLI-managed lifecycle
declaration supports **Linux x64 only** until native implementation and evidence
exist for additional platforms.

| Target | CLI M2 native acceptance | Current disposition |
| --- | --- | --- |
| Linux x64 | Real local-fixture backend install/update/uninstall | CONDITIONAL GO for backend; published CLI install/update NOT RUN |
| Linux ARM64 | Not implemented/validated | NOT RUN |
| Windows x64/ARM64 | Not implemented/validated | NOT RUN |
| macOS x64/ARM64 | Not implemented/validated | NOT RUN |

Legacy source installers are not an implicit M2 adapter and must not be launched
by the CLI as a fallback. Historical stable/RC installers remain unchanged.
Installing an RC source build under its separate candidate root is not equivalent
to testing a native Windows EXE/NSIS, macOS DMG or Linux AppImage.

## Linux x64 acceptance after authorization

Use a disposable standard-user host and separate Stable/RC data roots. For the
reviewed, published candidate first verify anonymous source/manifest/checksum
downloads. Run actual compiled standalone CLI with `--rc --check`,
`install personal --rc --yes`, repeat installation and
`uninstall personal --rc --yes` twice. Verify the packaged desktop executable,
installed version and launcher, no automatic GUI launch, software/runtime removal,
preserved profile/backup hashes, and untouched stable/Ollama sentinels.

Run real `update personal --rc` only after a second compatible published RC
exists. Do not test production updates against the legacy RC3 installer. When a
managed running instance is involved, verify that updates/uninstall refuse
operations until the app exits, keeping process-ownership checks fail-closed for
known instances. Distinguish fixture/command tests from native graphical checks.

## Windows/macOS future scope

First implement and review platform-specific ownership, launcher registration,
quiescence, runtime extraction and uninstall. Only then schedule ordinary-user
tests in disposable VMs with clean snapshots and no mounted real Personal data.
Do not use `--no-sandbox`, disable Gatekeeper/quarantine, change PowerShell
execution policy, or turn off antivirus simply to force a PASS.

Actual SQLite migrations, power-loss recovery, forced descendant termination
and cross-platform acceptance have not been demonstrated; do not claim otherwise.
Consult [RC4 readiness](1.1.0-rc.4-readiness.md) for release gates.
