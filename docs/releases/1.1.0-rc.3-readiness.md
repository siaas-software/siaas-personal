## Publication procedure — later authorized activity only

1. Review the draft PR, resolve conversations and merge it into develop through
   the protected PR process. Do not merge #20/#21, advance main or activate Actions.
2. Fetch develop and inspect changes since the baseline; stop if unrelated product
   changes entered the candidate. Create `release/1.1.0-rc.3` from the reviewed
   integrated develop and record its exact commit SHA.
3. From a clean committed checkout on that SHA, rerun the mandatory checks using
   Node 24.22.0. Archive any earlier local `dist-source` outside the checkout, then
   run `npm run release:source` and `npm run release:verify-source`. Both are local
   operations. Use `NODE_USE_ENV_PROXY=1` where required by the managed proxy,
   preserving TLS verification. The generated source archive must match this SHA,
   not an earlier PR commit. Retain hashes outside the source archive.
4. Recheck repository rules, release immutability, stable Latest=v1.0.0 and the
   absence of the RC3 tag/release. Verify API/upload connectivity and a repository-
   scoped Personal publishing credential with contents write permission; do not
   reuse the CLI upload token. Stop on missing access or failed checks.
5. Only after explicit authorization, create the immutable `v1.1.0-rc.3` tag on
   the verified release commit and push that tag. Never move an existing tag.
6. Create a GitHub draft release with title `SIAAS Personal v1.1.0-rc.3`, prerelease
   enabled and Latest disabled. Upload exactly the 12 files from verified
   `dist-source`, checking names, sizes, SHA-256 and tag/SHA before publication.
   Native installers and stable native updater metadata are prohibited assets.
7. Publish only after the draft inventory is complete. Run
   `npm run release:verify-source -- --published` from the exact tagged checkout;
   it checks anonymous bytes, digests, tag/SHA, prerelease flags and stable Latest.
   Separately confirm Latest is still exactly v1.0.0 and compare main, RC2 and
   existing stable release/asset identities with the saved baseline.
8. Record the publication evidence and remaining manual platform acceptance.
   Do not call publication complete until public verification passes.

No command above authorizes publication during this preparation task. Existing
release branches/tags, CLI v0.1.0, public website and repository protections stay
unchanged.
